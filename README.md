# Проектирование микросервисной архитектуры AI Chat Platform

## Описание проекта

Проектируем микросервисную архитектуру облачной AI-платформы — аналога ChatGPT.

Платформа предоставляет пользователям возможность взаимодействовать с универсальным AI-агентом через чат, сохранять историю диалогов, использовать различные LLM-модели и внешние инструменты, а также управлять подпиской.

## MVP — функциональные требования

1. **Auth & Users** — регистрация с подтверждением email, вход, управление профилем.
2. **Chats** — создание чатов, хранение истории сообщений, потоковая генерация ответов.
3. **Agent Runtime** — агентный цикл, вызов инструментов и управление контекстом внутри сервиса чатов.
4. **LLM Connector** — доступ к LLM-провайдеру.
5. **Tools** — базовые инструменты агента, например веб-поиск.
6. **Subscriptions** — тарифы Free / Pro, оформление и управление подписками через внешнего платёжного провайдера.
7. **Usage & Quotas** — учёт потребления токенов, ограничение запросов и ресурсов в зависимости от тарифа.

## Ответственность компонентов

### Клиент и сервисы

| Компонент | Ответственность |
| --- | --- |
| Web-клиент | Показывает регистрацию, настройки, историю и поток чата. Открывает внешнюю страницу оплаты и отображает статус счёта. |
| Web BFF | Собирает данные под веб-интерфейс. Читает профиль из Identity, список чатов из Chat & Agent, тарифы и остаток квоты из Subscription. Передаёт туда запросы на создание счёта и чтение его статуса. |
| Identity Service | Владеет аккаунтами, профилями, учётными данными и статусом подтверждения почты. Регистрирует, проверяет одноразовые коды, выполняет вход и меняет пароли, выпускает и обновляет токены. Публикует события пользователя и задачи на письма через outbox. |
| Chat & Agent Service | Владеет чатами, сообщениями и ссылками на вложения. Проверяет доступ к чату, резервирует квоту и фиксирует расход через Subscription. Agent Runtime собирает контекст, вызывает LLM и инструменты, формирует SSE для веба. MCP-клиент входит в этот сервис. |
| Subscription Service | Владеет каталогом `FREE` и `PRO`, текущими подписками, счётчиками квоты и счетами. Назначает тариф по умолчанию из своей БД по `UserCreated`, атомарно резервирует и списывает токены. Создаёт платёж через Payment Connector и активирует тариф после проверенного webhook и ставит напоминания об окончании подписки в `Email Notifications`. |
| Notifications | Читает задачи из `Email Notifications`, отправляет письма через API Email Provider и фиксирует результат отправки. |

### Интеграции

| Компонент | Ответственность |
| --- | --- |
| LLM Connector | Вызывает внешний Inference Provider по HTTPS, передаёт поток генерации и нормализует `usage` провайдера до `input_total`, `cache_read`, `output` и `cache_write`, если это поле доступно. |
| Payment Connector | Вызывает API внешнего Payment Provider и возвращает идентификатор платежа, ссылку на оплату и срок её действия, если провайдер его сообщает. |
| Tool Proxy (egress) | Направляет исходящие HTTPS-вызовы к Yandex Search API и пользовательским MCP-серверам. Ограничивает сетевые назначения для пользовательских URL. |
| Внешние провайдеры | Inference Provider выполняет генерацию и сообщает фактический расход. Payment Provider размещает страницу оплаты и отправляет webhook. Email Provider отправляет письма. Yandex Search API возвращает результаты веб-поиска. |
| External MCP Servers | Подключаемые пользователями внешние серверы. Отдают описания инструментов через `tools/list` и выполняют `tools/call` по MCP Streamable HTTP. |

### Очереди и хранилища

| Компонент | Ответственность |
| --- | --- |
| User Events | Асинхронно доставляет `UserCreated` из Identity в Subscription. |
| Email Notifications | Асинхронно доставляет задачи на письмо из Identity и Subscription в Notifications. |
| Users & Credentials DB | БД Identity. Аккаунты, профили, хеши паролей, данные подтверждения email и outbox. |
| Chats DB | БД Chat & Agent. Чаты, сообщения, ссылки на объекты S3 и конфигурация пользовательских MCP-подключений. Состояние обычного агентного цикла живёт в процессе выполнения. |
| Subscriptions DB | БД Subscription. Каталог тарифов и локальная связь `user_subscriptions.plan_id → plans.id`, квота за период, резерв и расход по `run_id`, счета и ID платежей. |
| Images (S3) | Объектное хранилище изображений, связанных с сообщениями. Метаданные и ссылки принадлежат Chat & Agent. |

В предложенном варианте развёртывания сервисы, коннекторы и Tool Proxy размещаются внутри `Kubernetes namespace: ai-chat`. Граница namespace показывает размещение. Маршрут из Chat & Agent к внешним MCP-серверам через Tool Proxy закрепляет `NetworkPolicy`.

## Архитектурный фокус

- Независимое масштабирование микросервисов.
- Синхронное и асинхронное взаимодействие сервисов.
- Потоковая передача ответов (SSE).
- Параллельная обработка разных чатов и порядок запросов внутри одного чата.
- Отказоустойчивость при сбоях LLM-провайдеров.
- Контроль квот и конкурентных запросов.
- Согласованность данных подписок и платежей.
- Наблюдаемость и распределённая трассировка.

## Результат проекта

**C4-модель архитектуры платформы:**

- **Level 1 — System Context:** пользователи и внешние системы.
- **Level 2 — Container Diagram:** текущие сервисы, хранилища и взаимодействия.
- **Level 3 — Component Diagram:** детализация Agent Runtime или другого ключевого сервиса.

## Следующие шаги

- Добавить в `User Events` события удаления и блокировки пользователя. Subscription Service и Chat & Agent Service будут обрабатывать события, относящиеся к их данным.
- Добавить Anti-Fraud Service для выявления подозрительной активности. Решение о статусе пользователя применяет Identity Service и сообщает об изменении остальным сервисам.
- При появлении долгих или прерываемых запусков добавить долговечное сохранение состояния исполнения агента (checkpointer). Redis рассматривать отдельно, если потребуется обмен событиями между API и исполнителями.

## Что можно добавить позже

- Долговременная память агента.
- MCP Registry и Skill Hub.
- Изолированные sandbox-окружения.
- Работа с файлами и генерация артефактов.
- Computer Use / Browser Automation.
- Долгоживущие фоновые агентные задачи (аналог ChatGPT Work / Claude Cowork).
- Multi-agent orchestration.
- Enterprise Workspaces и расширенный IAM.

Архитектуру проектируем с возможностью дальнейшего расширения до полноценной платформы автономных AI-агентов.

## Схемы и PNG

Исходная схема `Microservices.drawio` содержит текущую контейнерную диаграмму. Команда `make png` создаёт `Microservices.png`. При необходимости `make png` вызывает `scripts/install-deps.sh` для установки draw.io Desktop для macOS ARM в `.tools/`.

Причины изменений по версиям записаны в [логе решений](DECISIONS.md).

В [GitHub Releases](https://github.com/ilyascw/ai-th-microservices/releases) можно скачать исходный `.drawio` и PNG для просмотра. Краткое описание каждого релиза составляется по логу решений.

PNG, SVG и локальная копия draw.io в Git не добавляются.
